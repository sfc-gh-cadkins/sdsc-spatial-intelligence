Before you start

What you need

  • A Snowflake account with ACCOUNTADMIN access (or a role that can create databases, warehouses, and integrations)
  • Access to the Snowflake Marketplace (for Overture Maps, or bring your own geospatial dataset)
  • A CARTO account and workspace, if you want the CARTO MCP step (optional)
  • The skills/sdsc-setup skill from this repo, or the manual SQL below
    • Step 1 · Snowflake

    Set up the account foundation

    Create a dedicated database, warehouse, and schema layout. Keeping raw, analytics, and semantic layers in separate schemas makes grants easier later.

    Database → Warehouse → Schemas: RAW / ANALYTICS / SEMANTIC
    Step 2 · Snowflake Marketplace

    Bring in open geospatial data

    Search the Marketplace for Overture Maps (places, divisions, buildings, transportation). Import as a share - no ETL, queryable immediately alongside your own data.

    Optional: skip this step entirely and use only your own data. The semantic view and agent do not require Marketplace data to function.

    Step 3 · Snowflake

    Build a semantic view

    Define your business terms - what "exposure" or "risk tier" means - in a semantic view YAML. This is the governed translation layer every agent will use.

    Defines
    Tables, relationships, metrics, and business-friendly names
    Produces
    Correct SQL from a plain-English question, every time
    Step 4 · Snowflake

    Create a Cortex Agent

    Define an agent spec that references your semantic view, sets the orchestration model, and specifies the warehouse. The entire spec is JSON - version-controllable, no custom app required.

    Step 5 · CARTO (optional)

    Register the CARTO MCP connector

    Create a confidential SPA OAuth client in CARTO, register Snowflake's callback URL, then create the API integration and external MCP server in Snowflake. Attach the MCP server to your agent.

  • CARTO: create a confidential SPA OAuth Client, with a Client Secret
  • CARTO: register the callback URL https://identity.snowflake.com/oauth2/callback
  • Snowflake: create the API integration with the real Client ID and Secret (not the client's display name)
  • Snowflake: create the external MCP server, then attach it to your agent
    • Step 6 · Snowflake

    Set up a viewer role

    Create a role scoped to exactly what a workshop attendee (or business user) should see: the agent, the semantic view, the warehouse - nothing else. No access to raw tables, no ability to modify the agent spec.

    Everything above, automated

    Run the skill instead

    skills/sdsc-setup in this repo automates every required step above. Sample data loading (Hurricane Sandy NFIP claims) is included as an optional step - skip it and point the semantic view at your own dataset if you prefer.
