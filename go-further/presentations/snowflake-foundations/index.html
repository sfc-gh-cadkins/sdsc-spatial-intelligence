The idea

Turn a business question into governed SQL, automatically

Three primitives compose into everything you will see: a semantic view that defines what business terms mean, a Cortex Agent that orchestrates the conversation, and tools the agent can reach for - native SQL, Marketplace data, or an external MCP connector.

Component · the governed translation layer

Semantic Views

Business question → Semantic View → Correct SQL

A semantic view defines what "exposure" or "risk tier" means in your data, once, in one governed place. Every agent that uses it inherits the same definitions - no one has to know the underlying schema to ask a correct question.

  • Defined in YAML, version-controlled like code
  • Encodes relationships between tables, metrics, and business-friendly names
  • The same semantic view can back multiple agents
Component · the delivery mechanism

Cortex Agents & CoWork

A Cortex Agent orchestrates tools and answers questions in natural language. Snowflake CoWork is the chat interface where business users actually talk to it - no separate app, no export.

Zero code

Ask in plain English. The agent decides which tool to call and how to query it.

Governed

Data never leaves Snowflake. Access is controlled by the same roles and grants as everything else.

Composable

One agent can hold multiple semantic views and multiple tools, including external ones.

Component · native spatial types and functions

Location is a type, not just two columns

GEOGRAPHY models the Earth's surface with spherical WGS84 semantics and measures in metres. GEOMETRY is planar, and its units come from its coordinate reference system. Both support points, lines, and polygons, and native functions like ST_INTERSECTS and ST_DWITHIN let you ask "inside" and "near" directly in SQL.

GEOGRAPHY type
Native spatial type with functions like ST_DISTANCE, ST_WITHIN, ST_MAKEPOINT
H3 indexing
Built-in hexagonal spatial indexing for aggregating points into density grids at any resolution
Component · open data, zero ETL

Snowflake Marketplace

Third-party data - like the FEMA flood claims and county and ZIP boundaries in Snowflake Public Data (Free) - arrives as ready-to-query tables. No data pipeline, no procurement cycle, no file drops.

  • Import once, query immediately alongside your own data
  • Same agent interface works whether the data is yours or Marketplace-sourced
  • Combine proprietary claims data with open geospatial context in one conversation
Component · observability and cost governance

Cortex AI Gateway (preview)

One governed endpoint for apps and coding agents calling Snowflake-hosted models. In preview, on AWS commercial regions.

Usage observability

Traces and usage history per request: model, user, tokens, and cost.

Standard APIs

OpenAI Chat Completions and Anthropic Messages formats, authenticated with Snowflake tokens. No per-model keys.

Cost controls

Usage attributed to each Snowflake user, with budgets and per-user quotas set by administrators.

What SQL cannot do alone

Some spatial operations need a specialized engine

Geocoding, drive-time isochrones, and demographic enrichment are not SQL functions. That is where CARTO comes in - as a tool the same agent can reach for, without the user leaving CoWork.
