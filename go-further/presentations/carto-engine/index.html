The idea

Show, versus do

Native geospatial visualization means an agent can show you spatial data it already has. CARTO means the agent can do spatial operations that are not possible in SQL alone - geocoding, routing, enrichment - by reaching into CARTO as a specialized tool.

How it connects

CARTO MCP Server

Agent → MCP connector → CARTO engine

CARTO's spatial engine is registered as an external tool via the Model Context Protocol (MCP). The user never leaves CoWork - the agent decides when a question needs Snowflake SQL versus CARTO's engine, and calls the right one.

  • OAuth-governed, observable, revocable at any time
  • Access is per user - each person authorizes with their own CARTO account
  • The token inherits the signed-in user's own CARTO permissions
Capability

Geocoding

Convert addresses into map coordinates, at scale, as a callable tool. No separate geocoding service to integrate - the agent calls it mid-conversation.

Capability

Isochrones & routing

Drive-time and distance-based service area calculations - for example, a 30-minute drive radius around every adjuster office. This is not a SQL function; it requires a routing engine, and CARTO provides one as a tool.

Capability

Data Observatory enrichment

Append demographic, socioeconomic, and environmental context to your existing spatial data on demand. Turn a damage map into a resilience assessment without leaving the conversation.

Capability

Builder & Workflows

CARTO Builder creates interactive, shareable maps - the agent can generate one and hand back a URL. Workflows let an analyst build a reusable spatial pipeline once and publish it as an MCP tool any agent can call.
